# Feature Importance Audit — Техническое описание проекта

> Полное техническое описание скрипта `run_experiment.py`: архитектура, логика синтеза данных, входные и выходные параметры, и рекомендации по структуре проекта.

---

## 1. Архитектура и назначение скрипта

Скрипт представляет собой **автономный бенчмарк-стенд**, который воспроизводит и численно доказывает три фундаментальных порока дефолтной важности признаков (`feature_importances_`) в градиентном бустинге (LightGBM) по сравнению с Permutation Importance и TreeSHAP.

* **Стек:** `Python 3.10+`, `lightgbm`, `shap`, `scikit-learn`, `pandas`, `numpy`, `matplotlib`, `seaborn`.
* **Автономность:** скрипт не требует скачивания внешних датасетов из интернета. Все данные синтезируются по строгим формулам с известной базовой истиной (Ground Truth), что гарантирует 100% воспроизводимость (`np.random.seed(42)` в каждом эксперименте).

### Общая схема работы

```
run_experiment.py
├── experiment_1_cardinality_bias()      → fig1_cardinality_bias.png
├── experiment_2_multicollinearity_split() → fig2_multicollinearity_split.png
├── experiment_3_pruning_performance()   → fig3_pruning_performance.png
└── __main__: сбор результатов           → metrics.json
```

Каждая функция эксперимента:
1. Синтезирует данные с известной формулой целевой переменной.
2. Обучает `LGBMRegressor` (единообразно во всех экспериментах).
3. Вычисляет важности 3–4 методами.
4. Строит фигуру из двух subplots и сохраняет в `results/`.
5. Возвращает словарь / DataFrame результатов для записи в `metrics.json`.

## 2. Эксперимент 1: Искажение при разной мощности признаков (Cardinality Bias)

### Цель

Показать, что стандартный вызов `feature_importances_` в бустинге (по умолчанию считающий число сплитов — `importance_type='split'`) **дискриминирует важные бинарные/категориальные признаки** и **раздувает важность случайного шума с высокой мощностью** (`user_id`).

### Синтез данных ($N = 3\,000$ строк, 6 колонок)

#### Истинные сигналы:
| Признак | Распределение | Описание |
|---------|---------------|----------|
| `signal_cont_1` | $\mathcal{N}(0,\,1)$ | Непрерывный информативный |
| `signal_cont_2` | $\mathcal{N}(0,\,1)$ | Непрерывный информативный |
| `signal_binary_flag` | $\text{Bernoulli}(0.5)$ | Бинарный флаг: только 1 возможный порог сплита |

#### Чистые шумы (не связаны с таргетом):
| Признак | Распределение | Кардинальность |
|---------|---------------|----------------|
| `noise_high_card (user_id)` | $\text{Uniform}\{0,\,1,\,\ldots,\,999\}$ | ~1000 уникальных порогов |
| `noise_continuous` | $\mathcal{N}(0,\,1)$ | Непрерывная |
| `noise_binary` | $\text{Binomial}(1,\,0.5)$ | 2 значения |

#### Формула таргета $y$ (Ground Truth):
$$y = 1.5 \cdot x_1 + 1.5 \cdot x_2 + 2.0 \cdot x_{\text{binary}} + \varepsilon, \quad \varepsilon \sim \mathcal{N}(0,\,1.0)$$

> **Ключевое:** бинарный флаг дает сильный сдвиг (+2.0 к таргету), а шумы в формуле отсутствуют.

### Что происходит внутри

1. Выборка делится на **Train (70%)** и **Test (30%)** через `train_test_split(test_size=0.3, random_state=42)`.
2. Обучается `LGBMRegressor(n_estimators=100, learning_rate=0.05, importance_type='split')`.
3. Считаются **4 метрики важности** (нормализованные к 100% суммарного веса):

| # | Метод | Источник данных | Что измеряет |
|---|-------|-----------------|--------------|
| 1 | **MDI (Split)** | Train (встроенное) | Количество сплитов `model.feature_importances_` |
| 2 | **Permutation Train** | Train | Падение $R^2$ при перемешивании признака |
| 3 | **Permutation Test** | Test | Падение $R^2$ при перемешивании на отложенной выборке |
| 4 | **TreeSHAP Test** | Test | $\frac{1}{N}\sum_{i=1}^{N} |\phi_j(x_i)|$ через `shap.TreeExplainer` |

> **Нормализация Permutation:** отрицательные значения (шум, ухудшающий модель при присутствии) обрезаются через `np.maximum(0, ...)` перед делением на сумму.

### Результаты (по `metrics.json`)

| Признак | MDI (Split) | Perm Train | Perm Test | TreeSHAP Test |
|---------|:-----------:|:----------:|:---------:|:-------------:|
| `signal_cont_1` | 29.60% | 38.27% | 38.17% | 33.13% |
| `signal_cont_2` | 28.13% | 40.76% | 42.50% | 35.24% |
| `signal_binary_flag` | **8.53%** | 18.64% | 19.09% | 27.97% |
| `noise_high_card (user_id)` | **15.60%** | 1.09% | 0.14% | 1.88% |
| `noise_continuous` | 15.83% | 1.09% | 0.10% | 1.44% |
| `noise_binary` | 2.30% | 0.15% | 0.00% | 0.34% |

> **Главный вывод:** MDI отдал шуму `user_id` (15.60%) **почти вдвое больше**, чем реальному бинарному сигналу (8.53%). TreeSHAP и Permutation Test корректно отводят шуму ≤1.88%.

### Выходные артефакты

* **`fig1_cardinality_bias.png`** (300 DPI):
  * *Subplot A:* сгруппированные горизонтальные столбцы для всех 6 признаков по 4 методам.
  * *Subplot B:* фокусное сравнение приписанной важности шуму `user_id` — MDI (15.60%) vs TreeSHAP (1.88%) vs Permutation Test (0.14%).

## 3. Эксперимент 2: Расщепление при сильной корреляции (Multicollinearity Splitting)

### Цель

Показать, как появление скоррелированного дубликата («близнеца») **искусственно делит важность признака пополам**, опуская полезную пару ниже независимых признаков.

### Синтез данных ($N = 3\,000$ строк)

| Признак | Формула | Описание |
|---------|---------|----------|
| `feature_A` | $\mathcal{N}(0,\,1)$ | Базовый информативный сигнал |
| `feature_A_twin` | $x_A + \mathcal{N}(0,\,0.01)$ | Клон с $r > 0.999$ |
| `feature_B` | $\mathcal{N}(0,\,1)$ | Независимый информативный сигнал |
| `noise` | $\mathcal{N}(0,\,1)$ | Белый шум |

#### Формула таргета $y$:
$$y = 2.5 \cdot x_A + 1.5 \cdot x_B + \varepsilon, \quad \varepsilon \sim \mathcal{N}(0,\,0.5)$$

### Что происходит внутри

* **Сценарий 1 (без дубликата):** модель обучается на `[feature_A, feature_B, noise]`.
* **Сценарий 2 (с дубликатом):** модель обучается на `[feature_A, feature_A_twin, feature_B, noise]`.
* Замеряются доли важности каждого признака по MDI, Permutation и TreeSHAP.

> ⚠️ **Особенность реализации:** в этом эксперименте **нет train/test split** — обе модели обучаются и все метрики (MDI, Permutation, TreeSHAP) считаются на **полном датасете**. Это осознанный выбор: здесь нас интересует не предиктивная точность, а механизм перераспределения долей важности при добавлении коллинеарного признака.

### Результаты (по `metrics.json`)

**Сценарий 1 (без дубликата) — MDI:**
| Признак | MDI (%) |
|---------|:-------:|
| `feature_A` | 40.20% |
| `feature_B` | 42.33% |
| `noise` | 17.47% |

**Сценарий 2 (с дубликатом) — все методы:**
| Признак | MDI (%) | Permutation (%) | TreeSHAP (%) |
|---------|:-------:|:---------------:|:------------:|
| `feature_A` | 26.03% | 38.47% | 36.30% |
| `feature_A_twin` | 15.70% | 19.54% | 24.97% |
| `feature_B` | 40.87% | 41.79% | 38.00% |
| `noise` | 17.40% | 0.19% | 0.73% |

> **Главный вывод:** одиночный `feature_A` давал 40.20% в MDI, а после добавления близнеца разделился на 26.03% + 15.70% = 41.73% (сумма практически не изменилась). При этом независимый `feature_B` (40.87%) стал визуально «важнее», чем каждый из близнецов по отдельности.

> **Примечание:** TreeSHAP и Permutation тоже расщепляют важность между близнецами (это математически неизбежно при $r > 0.999$), но при этом корректно обнуляют шум: TreeSHAP даёт `noise` = 0.73%, Permutation = 0.19%, тогда как MDI раздувает шум до 17.40%.

### Выходные артефакты

* **`fig2_multicollinearity_split.png`** (300 DPI):
  * *Subplot A:* демонстрация расщепления в MDI (4 столбца: без дубликата → с дубликатом → копия → сумма).
  * *Subplot B:* сопоставление интерпретации коллинеарности тремя методами (сгруппированные столбцы для `feature_A`, `feature_A_twin`, `feature_B`).

## 4. Эксперимент 3: Пайплайн автоматического отбора и слом модели (Feature Pruning Pipeline)

### Цель

Имитировать работу реального ML-инженера: построить бейзлайн → отранжировать фичи по важности → отсечь нижние → измерить ошибку на тесте. Показать, **почему отбор по MDI ломает модель**, а TreeSHAP и Permutation улучшают её.

### Синтез данных ($N = 3\,000$ строк, 7 колонок)

#### Ядровые сигналы:
| Признак | Распределение | Коэффициент в $y$ |
|---------|---------------|:-----------------:|
| `credit_score` | $\mathcal{N}(0,\,1)$ | 1.6 |
| `income` | $\mathcal{N}(0,\,1)$ | 1.6 |
| `vip_flag (binary)` | $\text{Bernoulli}(0.25)$ | 2.2 |

#### Коллинеарный дубль:
| Признак | Формула | Описание |
|---------|---------|----------|
| `income_clone` | $\text{income} + \mathcal{N}(0,\,0.02)$ | Почти точная копия ($r > 0.99$) |

#### Три шума (не связаны с таргетом):
| Признак | Распределение | Описание |
|---------|---------------|----------|
| `noise_uniform` | $\mathcal{U}(-1,\,1)$ | Равномерный непрерывный шум |
| `noise_continuous` | $\mathcal{N}(0,\,1)$ | Нормальный шум |
| `client_id (noise)` | $\text{Uniform}\{1000,\,\ldots,\,9998\}$ | Псевдо-ID (высокая кардинальность) |

#### Формула таргета $y$ (Ground Truth):
$$y = 1.6 \cdot \text{income} + 1.6 \cdot \text{credit\_score} + 2.2 \cdot \text{vip\_flag} + \varepsilon, \quad \varepsilon \sim \mathcal{N}(0,\,0.5)$$

### Логика пайплайна (трёхэтапный сплит)

#### Этап 1: Разбиение данных
```
3000 строк
├── X_train (70% = 2100 строк)
│   ├── X_fit  (70% от train = 1470 строк) ← обучение ранжирующей модели
│   └── X_val  (30% от train = 630 строк)  ← Permutation и TreeSHAP
└── X_test  (30% = 900 строк)              ← финальная оценка RMSE
```

#### Этап 2: Ранжирование признаков
Модель обучается на $X_{\text{fit}}$. Считаются ранги признаков от 1 (лучший) до 7 (худший) по трём стратегиям:
- **MDI (Split)** — `model.feature_importances_` на $X_{\text{fit}}$;
- **Permutation** — `permutation_importance()` на $X_{\text{val}}$;
- **TreeSHAP** — `mean(|SHAP|)` на $X_{\text{val}}$.

#### Этап 3: Цикл отсечения (Pruning Loop)
Для каждого $k \in \{0, 1, 2, 3, 4\}$:
1. Оставляются топ-$(7 - k)$ признаков по рейтингу метода.
2. **Новая модель обучается с нуля** на полном $X_{\text{train}}$ (только на оставшихся фичах).
3. Замеряется **RMSE на строго изолированном** $X_{\text{test}}$.

### Результаты (по `metrics.json`)

#### Ранги признаков:
| Признак | Ранг MDI | Ранг Permutation | Ранг TreeSHAP |
|---------|:--------:|:----------------:|:-------------:|
| `credit_score` | 1 | 1 | 1 |
| `income` | 2 | 3 | 3 |
| `noise_uniform` | **3** | 7 | 6 |
| `income_clone` | 4 | 4 | 4 |
| `vip_flag (binary)` | **5** | 2 | 2 |
| `noise_continuous` | 6 | 6 | 5 |
| `client_id (noise)` | 7 | 5 | 7 |

> **Ключевая проблема MDI:** `noise_uniform` получил ранг 3 (выше `income_clone` и `vip_flag`!), а критически важный `vip_flag` опустился на 5-е место. При отсечении 3 нижних фичей MDI выбрасывает `vip_flag`, оставляя шум.

#### Кривые RMSE при отсечении:
| $k$ (удалено) | Осталось | RMSE (MDI) | RMSE (Perm) | RMSE (SHAP) |
|:---:|:---:|:---:|:---:|:---:|
| 0 | 7 | 0.5558 | 0.5558 | 0.5558 |
| 1 | 6 | 0.5509 | 0.5531 | 0.5509 |
| 2 | 5 | 0.5492 | 0.5532 | 0.5486 |
| 3 | 4 | **1.1111** | 0.5479 | 0.5479 |
| 4 | 3 | 1.1079 | **0.5470** | **0.5470** |

> **Главный вывод:** на шаге $k=3$ MDI выбрасывает `vip_flag`, и RMSE взлетает с 0.5492 до 1.1111 (**+100% ошибки**). В то же время Permutation и TreeSHAP монотонно улучшаются до 0.5470, потому что правильно удаляют только шум и коллинеарный клон.

### Выходные артефакты

* **`fig3_pruning_performance.png`** (300 DPI):
  * *Subplot A (Кривые качества):* по оси $X$ — число удалённых колонок, по оси $Y$ — RMSE на тесте. Красная линия MDI резко взлетает на шаге 3.
  * *Subplot B (Сравнительная таблица):* итоговая таблица рангов признаков по трём методам.

## 6. Параметры моделей

Во всех экспериментах используется единая конфигурация:

```python
lgb.LGBMRegressor(
    n_estimators=100,
    learning_rate=0.05,
    random_state=42,
    verbose=-1,
    importance_type='split'    # Считает количество сплитов, а не gain

```

Параметры Permutation Importance:
```python
permutation_importance(model, X, y, n_repeats=10, random_state=42, n_jobs=-1)
```

## 8. Известные особенности и ограничения

1. **Колонка MDI в Эксп. 1** в коде имеет заголовок `'MDI (Default rf.feature_importances_)'` с упоминанием `rf` (RandomForest) — это артефакт рефакторинга, модель на самом деле LightGBM.

2. **Эксперимент 2 не использует train/test split.** Все метрики считаются на полном датасете. Для целей эксперимента (демонстрация перераспределения долей) это допустимо, но при расширении стоит добавить hold-out split для чистоты.

3. **TreeSHAP не может дать ровно 0% для шума.** Поскольку `mean(|SHAP|)` всегда неотрицателен, любой признак, участвующий хотя бы в одном сплите дерева, получит ненулевой SHAP. Это не баг, а математическое свойство метода.

4. **Permutation Importance: отрицательные значения обрезаются до 0** (`np.maximum(0, ...)`). Это сделано для нормализации к процентам, но скрывает случаи, когда шум *помогал* модели (переобучение).

Если планируется расширение проекта (новые эксперименты, другие модели, CI), имеет смысл разделить скрипт на модули:

```
feature_importance_audit/
├── ARTICLE.md
├── scripts/
│   ├── README.md                       # Этот файл
│   ├── run_all.py                      # Точка входа: запускает все эксперименты
│   ├── config.py                       # Константы: N_SAMPLES, SEED, LGB_PARAMS, RESULTS_DIR
│   ├── data_synthesis.py               # Функции синтеза: make_cardinality_data(), make_collinear_data(), ...
│   ├── importance_methods.py           # Обёртки: compute_mdi(), compute_permutation(), compute_shap()
│   ├── experiments/
│   │   ├── exp1_cardinality_bias.py
│   │   ├── exp2_multicollinearity.py
│   │   └── exp3_pruning_pipeline.py
│   └── plotting/
│       ├── plot_exp1.py
│       ├── plot_exp2.py
│       └── plot_exp3.py
├── results/
│   ├── fig1_cardinality_bias.png
│   ├── fig2_multicollinearity_split.png
│   ├── fig3_pruning_performance.png
│   └── metrics.json
└── requirements.txt                    # Зависимости: lightgbm, shap, scikit-learn, ...
```

**Преимущества разделения:**
- Каждый эксперимент можно запускать отдельно.
- Логика визуализации отделена от вычислений — проще менять оформление.
- `config.py` — единая точка правды для гиперпараметров.
- `importance_methods.py` — переиспользуемые обёртки, устраняющие дублирование кода.
- `requirements.txt` — воспроизводимость окружения.

> **Текущий масштаб проекта (429 строк, 3 эксперимента)** вполне позволяет оставить всё в одном файле. Разделение стоит делать при превышении ~600 строк или добавлении 4+ экспериментов.
